# log-collection

Collect logs in a Kubernetes environment using shell scripts and Filebeat.

### Version Update:

Retrieves the main application's container ID via a Python script and renames the created directory to match this ID. Currently supports only a single main application container.

### Description

When an application runs in Kubernetes, it can have multiple pod replicas. Each replica may generate log files with different information, and not all of these log files can be read using the `docker logs` command.

This project provides a configuration method to differentiate the log files generated by containers in each pod and store them in a centralized storage location.

Furthermore, for distributed applications, it is necessary to consider re-aggregating all logs back into their original file formats. This requires a process of unified aggregation after the differentiated collection.

### Docker Build Command:

```bash
docker build -t jasko/log-collect:0.1 -f Dockerfile .
```

### Configuration

**Shared Storage Directory**
`/opt/cephfs/projA`

**Log Staging Directory (Shared Volume)**

  * **name**: `logvol`
  * **source**: `/usr/local/tomcat/logs`
  * **target**: This is set via the `LOG_LOCATION` variable, but the path must also be specified in the volume mount configuration.

**Log Collector Environment Variables:**

```yaml
env:
  - name: LOG_LOCATION   # Log path, must be consistent with the logvol target path
    value: /opt/logs
  - name: INTERVAL       # Time interval for log collection (in seconds)
    value: 5
  - name: LOGOPT         # Parameters for rsync
    value: -a
```

### Check Container Status

To check the running status of the log collector container:

```bash
kubectl logs -f $PODNAME -c logcollector
```
